ACCESSIBILITY

Accessibility

How the tracker approaches keyboard use, contrast, labels and responsive access, plus its current limitations.

Our approach

We aim to make the tracker usable across desktop and mobile with clear labels, readable contrast, responsive layouts, descriptive alternative text, keyboard-focus indicators and accessible form controls.

Keyboard access

Interactive controls such as buttons, links, search fields, selects and bus results are designed to be reachable with a keyboard. Map interactions can still depend on the third-party map library.

Color

Color is not intended to be the only way we communicate status. Text labels such as “Live GPS”, route names and movement states accompany visual indicators.

Known limitations

The live map is provided by a third-party mapping stack, so some map interactions and provider controls may not have identical accessibility behavior to our own interface.

Browser location permissions and notification prompts are controlled by the browser and operating system.

Feedback

Accessibility issues should be reported through the project's public repository so they can be reproduced and corrected.

Report an accessibility issue
We do not claim formal WCAG conformance without a completed accessibility audit. This page describes the practices and limitations of the current interface.
