PRIVACY

Privacy Notice

What the tracker collects, why it is used, where third-party services are involved, and how you can control local data.

What we collect

Noida Bus Tracker does not require an account and does not intentionally ask for your name, phone number, email address, or home address.

Location

When you choose Use my location, your browser provides latitude and longitude to the website so the backend can find nearby buses. Location access is initiated by you through the browser's permission prompt.

Searches and address lookup

When you search for a place, the text is sent to our backend for place suggestions. If those results are incomplete, the browser also sends the search text directly to OpenStreetMap’s Nominatim search service at nominatim.openstreetmap.org as a fallback.

When an address label is requested for a selected or detected location, the browser sends the selected latitude and longitude directly to Nominatim’s reverse-geocoding service to retrieve a readable address. These coordinates may be precise depending on the location you selected or shared.

Local browser data

The site may store theme preference, dismissed notices, favourites, nearby-bus history, nearby-alert preferences, and your choice to hide the welcome notice after acknowledgement in your browser's local storage.

Why we use it

We use location and search information only to provide the nearby-bus and map features you request. Local storage is used to keep product preferences and support features such as movement history, favourites and dismissed notices.

Bus reports

If you submit a report, we receive the bus identifier, report category, any optional note you enter, and the consent value required by the form. Do not include personal information in the note.

Reports are submitted through Web3Forms. Netlify documents that form submissions are stored in its user database and may include submission metadata, and recommends active management and deletion when forms contain personal information.

Third parties

Map tiles use MapTiler services and OpenStreetMap data. Browser-based fallback place searches and reverse address lookups use OpenStreetMap Foundation’s Nominatim service, which receives the search text or coordinates described above and request network metadata. Approximate IP-area analytics uses ipapi.co for a location lookup; the visitor IP is sent to that provider when a lookup is attempted. The website is hosted on Netlify and the bus API is hosted on Render. These providers have their own terms and privacy practices.

Analytics data storage

Analytics events are stored in the database configured for the backend deployment. The application uses PostgreSQL when its database connection is configured and can use an ephemeral SQLite fallback in local or fallback deployments. The active production database host is selected by deployment configuration and is not hard-coded in the website source.

Analytics

The website and Android app record product events such as page views, app opens, first opens, refreshes, bus selections, searches, reports, and feature activity so the independent project can understand which features need improvement. Pseudonymous installation/visitor and session identifiers are used to count usage over time; they are not your name, email address, phone number, or exact home address. The Android app may send device brand, manufacturer, model, Android version, app version, and language for aggregated compatibility and usage reports. These device details are not intended to identify an individual.

Android installation and approximate first-open area

The app sends a first-open event once per locally recorded installation when this analytics feature is enabled in the app version. This provides a count of installation instances first observed after the feature rollout; it is not an exact Google Play download count or a guaranteed count of unique physical phones. Clearing app data or reinstalling may create a new installation identifier. At first open, the backend may use the network IP address for an approximate area lookup through ipapi.co. This is not GPS and does not prove where the app was installed. Areas are rounded and shown only as aggregates with at least 3 installation identifiers. You can disable analytics at any time under App settings → Usage analytics. Disabling it stops future app analytics events from being sent; it does not delete events already received by the server.

Approximate area analytics

To understand which broad areas use the tracker, when a page view or app open is recorded, the server may use the request IP address to request approximate geographic coordinates from IP geolocation provider ipapi.co. IP-based location is imprecise and may identify a network or mobile carrier gateway rather than your actual location. The tracker does not save the raw IP address in its analytics database. The provider receives the IP address to perform the lookup and may process it under its own privacy policy. Approximate coordinates are rounded before being stored with analytics events. Admin heat maps show only aggregated areas with at least 3 recorded visits or shares, rather than individual visitor locations. If IP geolocation fails, the visit is still counted in general analytics but is not placed on the map. Hosting and network providers may independently process IP addresses in server logs.

Approximate location sharing

The optional Help improve this area control requires a separate confirmation. When you approve it, the browser location is rounded to about 1 km before it is sent to our backend. Admin analytics only displays aggregated areas that have at least 3 shares. You can decline this feature and continue using the tracker.

Your controls

You can deny browser location permission, stop using the location feature, clear site data in your browser, or reset the local data stored by this site.
